# Universal MCP tool proxy, Godot first

Owner request: expose configured upstream MCP servers as namespaced sub-tools of
chatgpt-mcp, beginning with Godot AI; do not hard-code Godot as the only upstream.

## Delivered contract

- Opt-in `proxy.upstreams`; no upstreams means unchanged native tools.
- Stdio, Streamable HTTP, and explicitly selected legacy SSE transports.
- `<upstream>.<tool>` registration with original argument/output schemas,
  annotations, custom metadata, structured results and image content.
- Runtime-owned reusable upstream sessions, bounded discovery/execution,
  namespace isolation, allowlists, per-upstream concurrency and no proxy-level
  automatic replay of tool calls.
- Independent upstream credentials from named environment variables or files;
  downstream authentication is never forwarded and status excludes credentials.
- Shutdown ownership includes failed initialization and stalled SSE startup.
- `proxy.status` and `proxy.refresh` for diagnosis and catalogue refresh.

## Runtime boundary

The requested public checkout was initially empty and was cloned. The unrelated
installed checkout had local changes and was left untouched.

This delivery changes the requested repository. It does **not** replace the
currently connected Overdeck runtime: that independently managed installation
contains additional policy and execution behavior absent from this public source.
Replacing it with this repository's release would remove existing protections.
Any live adoption must preserve its owning source and managed deployment contract.

The real-Godot CI proof uses the real MCP server and its attach bridge, not a mock,
but does not have a running Godot editor attached. Editor manipulation and live
connector catalogue refresh are therefore not claimed as verified deployment.
No existing tunnel, router, active backend, private configuration or credentials
were changed.
